# Code of Conduct

## Our pledge

We want taking part in GitPulse to be a welcoming, harassment-free experience for everyone,
whatever their age, body size, visible or invisible disability, ethnicity, sex characteristics,
gender identity and expression, level of experience, education, socio-economic status,
nationality, personal appearance, race, caste, colour, religion, or sexual identity and
orientation.

GitPulse is a tool about people's public work, so this matters twice over: we treat each other,
and the developers whose activity the tool shows, with the same respect.

## Expected behaviour

- Be kind and patient, especially with newcomers and people whose first language is not English.
- Discuss the code and the idea, not the person. Assume good intent.
- Give and accept constructive feedback gracefully, and own your mistakes.
- Focus on what is best for the project and its users.

## Unacceptable behaviour

- Harassment, insults, or derogatory comments, in public or in private.
- Sexualised language or imagery, and unwelcome sexual attention.
- Trolling, deliberate derailing, or personal or political attacks.
- Publishing someone else's private information (such as an address or email) without explicit
  permission.
- Using GitPulse, its issues or its discussions to single out, rank or shame individual
  developers.
- Any other conduct that would reasonably be considered inappropriate in a professional setting.

## Scope

This code applies in all project spaces (issues, pull requests, discussions, reviews) and when
someone is representing the project elsewhere.

## Reporting

If you experience or witness unacceptable behaviour, contact the maintainer privately,
[@abhiramchendika-svg](https://github.com/abhiramchendika-svg), using the contact details on
their GitHub profile. You can also use GitHub's
[report content](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)
feature. Every report is reviewed promptly and fairly, and the reporter's privacy is respected.

## Enforcement

The maintainer may take any action they consider appropriate, for example:

1. **Correction:** a private, written explanation of why the behaviour was inappropriate.
2. **Warning:** a warning with consequences for continued behaviour.
3. **Temporary ban:** no interaction with the project for a set period.
4. **Permanent ban:** for a pattern of violations or a serious single one, such as harassment.
